<objective>
Wire dead-token pruning into a thin `PushSendService` send seam — the class Phase 9's triggers will reuse — that calls `PushProvider` and, on an FCM `UNREGISTERED` result, soft-deactivates the token via `DeviceTokenService`. Add the provider-mocked verification suite: contract tests asserting payload shape and token-pruning behavior against a mocked provider (normal CI), plus a disabled-by-default `validate_only` dry-run smoke test that runs manually when real Firebase credentials are present.

Implements decisions D-04 (soft-deactivate dead tokens), D-10 (mocked-provider contract tests in normal CI), and D-11 (validate_only smoke test as a disabled-by-default @Tag("smoke") test).
</objective>

<must_haves>
- `PushSendService.send(token, payload)` calls `PushProvider.send` and, when the result status is `UNREGISTERED`, deactivates that token via `DeviceTokenService.deactivateToken` (PUSH-03).
- Only `UNREGISTERED` prunes — `SUCCESS` and `ERROR` (transient) results leave the token active.
- Mocked-provider contract tests assert payload shape (captured `PushPayload`) and the token-pruning branch (PUSH-12, D-10) and run in normal CI with no real Firebase.
- The `validate_only` dry-run is a separate `@Tag("smoke")` test, disabled by default, not wired into standard CI (D-11).
- Pruning logic lives in the send-orchestration service, not inside the raw `PushProvider` implementation (keeps the provider Firebase-confined and reusable by Phase 9).

truths:
  - "D-04: UNREGISTERED → soft-deactivate (active=false + deactivatedAt), no hard-delete"
  - "D-10: Mocked-provider contract tests run in normal CI — assert payload shape and token-pruning behavior"
  - "D-11: validate_only dry-run is a separate @Tag(\"smoke\") test, disabled by default, opt-in with real creds"
  - "PUSH-03: Backend deactivates tokens FCM reports as UNREGISTERED so dead tokens stop receiving sends"
  - "PUSH-12: Send-decision-independent payload shape and token pruning covered by mocked-provider tests; validate_only smoke test confirms real auth/payload"

prohibitions:
  - statement: "Non-UNREGISTERED results (SUCCESS, ERROR) MUST NOT deactivate a token"
    status: resolved
    verification: "TokenPruningTest asserts ERROR/SUCCESS leave active=true; only UNREGISTERED deactivates"
  - statement: "The validate_only smoke test MUST NOT run in the default CI test task"
    status: resolved
    verification: "FcmSmokeTest is @Tag(\"smoke\") + @Disabled (or excluded by the default test task); default run does not execute it"
  - statement: "Pruning MUST NOT live inside FcmPushProvider/LoggingPushProvider"
    status: resolved
    verification: "deactivation call is in PushSendService, not in the PushProvider implementations"
</must_haves>

<threat_model>
ASVS L1 — block on: high.

- **T-08-06 (erroneous mass-deactivation / availability, MED — mitigated):** A bug that deactivates tokens on transient errors (`UNAVAILABLE`/`INTERNAL`, mapped to `ERROR`) would silently disable delivery to live devices. **Mitigation:** `PushSendService` deactivates ONLY on `PushSendStatus.UNREGISTERED`; `TokenPruningTest` asserts both branches — `ERROR` leaves `active=true`, `UNREGISTERED` deactivates. No mass/batch deactivation path exists.
- **T-08-07 (smoke test leaking real creds into CI, LOW — mitigated):** The dry-run smoke test requires a real service account. **Mitigation:** it is `@Tag("smoke")` + disabled by default and reads creds from the env only when opted in; the default `test` task never runs it, so no credential is required or exposed in CI.
</threat_model>
