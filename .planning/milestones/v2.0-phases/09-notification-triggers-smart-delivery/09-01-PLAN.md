<objective>
Build the in-memory, single-instance presence and active-conversation registry that drives the Phase 9 "offline + inactive" send decision. It tracks which users have a live STOMP session (presence) and which conversation topics each session is subscribed to (active conversation), fed by STOMP session lifecycle events and cleared on disconnect.

Purpose: This registry is the sole source of truth for the send decision in Plan 02 (D-02 match presence suppression, D-04 message offline+inactive). Active-conversation is inferred purely from the client's existing `/topic/chat/{conversationId}` STOMP subscription with no new client contract (D-03). Without it, no trigger can decide whether to suppress a push.
Output: `PresenceRegistry` (state + queries), `StompPresenceListener` (STOMP event → registry), and unit tests proving the state transitions (PUSH-08).
</objective>
