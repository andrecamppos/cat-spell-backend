<objective>
Wire the two domain triggers to the push pipeline asynchronously: define lightweight application events, publish them from the existing `@Transactional` write methods (`MatchService.createMatch`, `ChatService.sendMessage`), and consume them with a single `@Async @TransactionalEventListener(phase = AFTER_COMMIT)` listener that delegates to `PushNotificationService` (Plan 02). This guarantees a push only fires after the DB commit and never blocks or rolls back persistence (PUSH-10, D-07).

Purpose: Completes the phase — connects real match/message events to smart delivery without coupling chat/match to the push module (they depend only on `ApplicationEventPublisher`) and without any push I/O on the request thread.
Output: `PushEvents.kt` (event types), `PushNotificationListener` (async AFTER_COMMIT), event publication in `MatchService`/`ChatService`, and an integration test proving async, commit-gated, non-blocking behavior (PUSH-10).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Request thread → async listener | FCM I/O is moved off the request/persistence thread; a failure here must not affect the write |
| Transaction commit → side effect | Push must fire only after a successful commit, never on rollback |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-9-02 | Denial of Service | Synchronous/failing FCM call on the message path | high | mitigate | `@Async @TransactionalEventListener(AFTER_COMMIT)` isolates FCM I/O on a separate thread post-commit; the listener try/catches and logs. Integration Test B asserts a slow/failing push does not block or roll back persistence. |
| T-9-07 | Repudiation/Consistency | Push fired for a match/message that later rolled back | medium | mitigate | AFTER_COMMIT phase guarantees the listener runs only when the transaction commits; events published pre-commit are discarded on rollback. |
| T-9-08 | Information Disclosure | Duplicate match notification on idempotent createMatch | low | mitigate | Event published only on the new-save branch, not on existing-match returns or duplicate-key fallback. |
</threat_model>
