<action>
Replace findDiscoveryFeed native query with UNION ALL query wrapped in subquery:

Cat card branch:
- SELECT 'CAT' AS type, cp.user_id AS user_id, up.display_name, (user photo subquery) AS user_photo_thumbnail, distance calc AS distance_km, cp.id AS cat_id, cp.name AS cat_name, cp.age AS cat_age, cp.age_unit AS cat_age_unit, cp.breed AS cat_breed, cp.bio AS cat_bio, (cat photo subquery) AS cat_photo_thumbnail
- FROM cat_profiles cp JOIN user_profiles up ON up.user_id = cp.user_id
- WHERE ROW_NUMBER() OVER (PARTITION BY cp.user_id ORDER BY cp.created_at ASC) = 1 — one cat per user, first-created
- Same distance/gender/age/completeness filters as current query
- User photo EXISTS check (existing)
- Cat photo EXISTS check (existing)
- Exclusion: NOT EXISTS (SELECT 1 FROM swipes s WHERE s.swiper_id = :requesterId AND s.target_user_id = cp.user_id)
- Self-exclusion: cp.user_id != :requesterId

Human card branch:
- SELECT 'HUMAN' AS type, up.user_id, up.display_name, (user photo subquery) AS user_photo_thumbnail, distance calc AS distance_km, NULL AS cat_id, NULL AS cat_name, NULL AS cat_age, NULL AS cat_age_unit, NULL AS cat_breed, NULL AS cat_bio, NULL AS cat_photo_thumbnail
- FROM user_profiles up
- WHERE NOT EXISTS (SELECT 1 FROM cat_profiles WHERE user_id = up.user_id) — catless users only
- Same distance/gender/age/completeness filters
- User photo EXISTS check
- Exclusion: NOT EXISTS (SELECT 1 FROM swipes s WHERE s.swiper_id = :requesterId AND s.target_user_id = up.user_id)
- Self-exclusion: up.user_id != :requesterId

Wrap UNION ALL in: SELECT * FROM (...) AS feed ORDER BY random() LIMIT :pageSize OFFSET :offset

Use ROW_NUMBER() as a subquery/CTE for the cat branch to avoid window function in WHERE:
WITH ranked_cats AS (SELECT *, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at ASC) AS rn FROM cat_profiles) — then filter rn = 1.

Add new repository method for human swipe duplicate detection:
fun existsBySwiperIdAndTargetUserIdAndCatProfileIsNull(swiperId: UUID, targetUserId: UUID): Boolean
</action>

- Both branches share identical distance/gender/age/completeness filters

   - catId = proj.getCatId() (nullable)
   - catName = proj.getCatName() (nullable)
   - catAge = proj.getCatAge() (nullable)
   - catAgeUnit = proj.getCatAgeUnit() (nullable)
   - breed = proj.getCatBreed()

   - catPhotoThumbnail = proj.getCatPhotoThumbnail()
   - userPhotoThumbnail = proj.getUserPhotoThumbnail()
   - distanceKm = proj.getDistanceKm()
   Return FeedResponse(cards = items, cursor = nextCursor) — field is now `cards`

2. swipe() — branch on catId vs targetUserId:
   Add validation at method start:
   require((request.catId != null) xor (request.targetUserId != null)) { "Exactly one of catId or targetUserId must be provided" }

   If request.catId != null (cat swipe):
   - Same as current flow: look up CatProfile, get owner, check self-swipe (catOwnerId == userId), check duplicate via existsBySwiperIdAndCatProfileId, save Swipe(catProfile = cat, targetUser = targetUser)

   If request.targetUserId != null (human swipe):
   - Look up target User by targetUserId, throw ResourceNotFoundException if not found
   - Self-swipe check: request.targetUserId == userId → throw SelfSwipeException
   - Duplicate check: swipeRepository.existsBySwiperIdAndTargetUserIdAndCatProfileIsNull(userId, request.targetUserId)
   - Save Swipe(swiper = swiper, catProfile = null, targetUser = targetUser, action = request.action)

   Mutual match detection (both paths): unchanged — findBySwiperIdAndTargetUserIdAndAction already works on user IDs. For cat swipes, targetUserId is the cat owner. For human swipes, it's the targetUserId directly.

3. Add getUserProfile() method for human card detail:
   fun getUserProfile(requesterId: UUID, userId: UUID): OwnerProfileResponse
   - Look up UserProfile by userId, throw ResourceNotFoundException if not found
   - Calculate age from dateOfBirth
   - Get active user photos
   - Get user's cats (will be empty for catless users, populated for cat owners viewed from human card)
   - Return OwnerProfileResponse (reuse existing DTO — it has userId, displayName, bio, age, gender, photos, cats fields)
</action>
