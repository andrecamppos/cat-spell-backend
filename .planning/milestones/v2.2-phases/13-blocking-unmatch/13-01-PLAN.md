<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → discovery feed query | Requester-supplied identity is bound to :requesterId; the feed must never surface a user on either side of a block. |
| entity ↔ migration | Block/Match entity mappings must match V19/V20 or the app fails ddl-auto validate at boot. |
| DB constraint layer | Self-block and duplicate-block must be rejectable at the DB even if a service check is bypassed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-01 | Information Disclosure | findDiscoveryFeed leaking a blocked user on one branch/direction | high | mitigate | Bidirectional NOT EXISTS added to BOTH UNION branches against :requesterId (Task 3, MOD-02/D-03). |
| T-13-02 | Tampering | Rediscovery ban leaking in from a non-block source (unmatch behaving like block) | high | mitigate | Feed filter reads the blocks table ONLY; teardown swipe-clear removes exclusions, never adds (Task 3, D-09). |
| T-13-03 | Elevation of Privilege | Self-block corrupting pair state / self-referential rows | medium | mitigate | DB CHECK (blocker_id <> blocked_id) in V19 backstops the service-layer reject (Task 1, D-12). |
| T-13-04 | Denial of Service | Hard-delete teardown destroying report evidence / breaking immutable history | high | mitigate | Soft-state columns (ended_at/ended_reason) only; deleteSwipesBetween touches swipes exclusively (Task 1/3, D-07). |
| T-13-05 | Tampering | Schema drift (entity vs V19/V20) blocking prod boot | high | mitigate | Column parity between Block/Match fields and migrations; verified by Testcontainers boot (Task 1–3). |
| T-13-06 | Denial of Service | Unindexed reverse block lookup degrading the feed as blocks grow | medium | mitigate | idx_blocks_reverse on (blocked_id, blocker_id) added in V19 (Task 1). |
| T-13-SC | Tampering | npm/pip/cargo installs | low | accept | No new dependencies this phase — nothing to audit. |
</threat_model>
