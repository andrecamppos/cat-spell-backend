<objective>
Expose the HTTP surface and flip the register contract. Add `VerifyEmailRequest` /
`ResendVerificationRequest` DTOs; change `POST /api/auth/register` to create an unverified user, send
the first verification email, and return 201 with a generic body and NO tokens (D-01); add
`POST /api/auth/verify-email` (200, no tokens, D-02) and `POST /api/auth/resend-verification` (202
generic, D-04). Prove the full register→verify→login flow, the 403 gate, resend enumeration-safety,
and single-use/expired token rejection end to end with a stubbed EmailSender.

Purpose: Turn Plan 03's service + gate into the public, validated, tested verification API.
Output: DTO additions, the `AuthService.register` no-token change, three controller endpoints, and
`EmailVerificationIntegrationTest.kt`.

Note: The register contract change breaks ~18 existing integration tests that assume register returns
tokens / that login works for freshly-registered users. Those suite-wide fixes are done in Plan 05
(wave 4); this plan only adds the new EmailVerificationIntegrationTest and leaves the legacy suite for
Plan 05 (each plan's own verify gate is scoped to its own tests).
</objective>
