## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → email transport | The raw verification token leaves the system only inside the rendered email body. |
| config → runtime | The deep-link base URL is environment-supplied; a wrong value would misdirect verification links. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-06 | Information Disclosure | Raw token leaked to logs/URLs | high | mitigate | Token appears only inside the rendered email link, never logged; verify endpoint takes the token in the JSON body not a server URL (Task 1, D-07) — prohibition authored. |
| T-11-07 | Spoofing | Real network email during CI reveals infra / flakes | medium | mitigate | Renderer only builds an EmailMessage; the existing no-op/logging EmailSender handles delivery (stubbed in tests, EMAIL-02). |
| T-11-08 | Tampering | Wrong/attacker-controlled verify-email-url misdirects links | low | accept | Value is operator-supplied env config with a safe catspell:// default; out of app trust boundary. |
| T-11-SC | Tampering | npm/pip/cargo installs | high | accept | No new dependencies this phase — nothing to audit. |
</threat_model>
