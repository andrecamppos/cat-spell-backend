<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API | Untrusted file metadata (contentType, fileName) from mobile app |
| Client → S3 | Direct file upload via presigned URL — content-type and size enforced by URL conditions |
| API → S3 | Server downloads uploaded files for thumbnail generation |
| S3 → API | Untrusted file content from S3 processed for thumbnails |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Spoofing | Photo ownership | mitigate | userId extracted from JWT, never from request. PhotoService verifies findByIdAndUserId before confirm/delete/reorder |
| T-02-08 | Tampering | File upload type | mitigate | D-08: contentType validated server-side (JPEG/PNG only). Presigned URL includes content-type condition. Extension derived from validated contentType, not user input |
| T-02-09 | Tampering | File size | mitigate | D-08: presigned URL includes content-length-range condition (max 10MB). StorageService enforces max 10485760 bytes |
| T-02-10 | Tampering | Malicious image | accept | Thumbnailator processes via ImageIO which handles common formats safely. OOM prevented by 10MB size limit. No execution of embedded content. Accept residual risk for v1 |
| T-02-11 | Information Disclosure | S3 keys | mitigate | S3 keys use UUIDs not user-identifiable names. Presigned URLs expire in 15 min. Bucket is private (no public access) |
| T-02-12 | Denial of Service | Photo upload spam | mitigate | D-05: max 6 photos per user. Presigned URL expiry (15 min) limits window. No anonymous uploads (JWT required) |
| T-02-13 | Denial of Service | Thumbnail generation | mitigate | 10MB max file size. Thumbnail generation is synchronous but bounded. One photo at a time per request |
| T-02-14 | Elevation of Privilege | Cross-user photo access | mitigate | All photo operations filter by userId from JWT. findByIdAndUserId returns null for non-owned photos → 404 |
</threat_model>
