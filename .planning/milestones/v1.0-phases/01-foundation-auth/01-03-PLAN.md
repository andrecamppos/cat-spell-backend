    1. handleValidation(MethodArgumentNotValidException): Returns 400 ProblemDetail with title "Validation Error", detail "Validation failed".     2. handleDuplicateEmail(DuplicateEmailException): Returns 409 ProblemDetail with title "Conflict", detail "Email already registered".

    3. handleInvalidCredentials(InvalidCredentialsException): Returns 401 ProblemDetail with title "Unauthorized", detail "Invalid credentials" per D-15. Never reveals whether email exists or password is wrong.

    4. handleInvalidToken(InvalidTokenException): Returns 401 ProblemDetail with title "Unauthorized", detail from exception message.

    5. handleResourceNotFound(ResourceNotFoundException): Returns 404 ProblemDetail.

    6. handleGenericException(Exception): Returns 500 ProblemDetail with title "Internal Server Error", detail "An unexpected error occurred" (generic per D-15). Log full stack trace at ERROR level server-side. Never expose stack trace or internal details in response.

    7. handleConstraintViolation(ConstraintViolationException): Returns 400 ProblemDetail with violations array (for @Validated on path/query params).

    Update application.yml: Set spring.mvc.problemdetail.enabled=true to enable RFC 7807 for Spring's built-in errors (404 Not Found, 405 Method Not Allowed).

    Update AuthService.kt: Replace generic ResponseStatusException throws with domain exceptions — throw DuplicateEmailException for duplicate email on register, throw InvalidCredentialsException for login failures. Import from com.catspell.api.common.exception.

    Update AuthController.kt: Remove any try/catch blocks — let GlobalExceptionHandler handle exceptions centrally. Ensure @Valid annotation is on request body parameters.
