<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API (authenticated) | change-password / change-email require a valid JWT; principal is trusted only after filter validation |
| client → API (public) | confirm-email-change is reachable unauthenticated; the single-use token is the only credential |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-04-01 | Elevation of Privilege | endpoint auth posture | high | mitigate | Only confirm-email-change is whitelisted; change-password/change-email keep JWT auth (no @SecurityRequirements, absent from permitAll + shouldNotFilter). |
| T-12-04-02 | Spoofing | extractUserId principal | high | mitigate | userId is taken from the JWT-validated SecurityContext principal, never from the request body. |
| T-12-04-03 | Denial of Service | change-email request flooding | medium | mitigate | change-email added to RateLimitFilter.AUTH_PATHS for per-IP throttling (plus per-target-email guard in 12-03). |
| T-12-04-04 | Tampering | @Valid DTO bounds | low | mitigate | @field:Size(min=8) and @field:Email reject malformed input at the controller boundary before service logic. |
</threat_model>
