<objective>
Create the persistence layer for pending email changes: the `EmailChangeRequest`
JPA entity, its repository (with the atomic single-use `markUsed` claim), and the
Flyway V18 migration that creates the `email_change_requests` table. This is the
storage backbone for the change-email request/confirm flow (D-04).

Purpose: A pending new address must be stored durably and claimed exactly once so
the account email only switches on a valid, single-use confirmation (ACCT-04).
Output: One new entity, one new repository, one new migration file.
</objective>

|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01-01 | Tampering | EmailChangeRequestRepository.markUsed | high | mitigate | Atomic conditional UPDATE (`WHERE used_at IS NULL`) makes double-confirm apply at most once — no read-check-write race. |
| T-12-01-02 | Information Disclosure | email_change_requests.token_hash | medium | mitigate | Store only SHA-256 hash of the token (never the raw token); column is UNIQUE for single-use lookup. |
| T-12-01-03 | Denial of Service | orphaned rows on user delete | low | mitigate | FK `ON DELETE CASCADE` removes pending requests when the user is deleted. |
