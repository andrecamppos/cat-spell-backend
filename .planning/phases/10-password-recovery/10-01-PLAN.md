Noun now (arguably) plural: message-delivery seams (push + email). Decision: **no-change /
add-alongside (accepted, low-risk)**. `EmailSender` and `PushProvider` are independent delivery
domains with different payload shapes and recipients; there is no shared "notification" abstraction
being generalized, so promoting a common super-abstraction would be premature. `EmailSender` is the
FIRST email seam (not a second variant of an existing email abstraction), so the identity-model
question does not bite. What would force a later promote: a phase that needs to route the same
logical notification across both channels. Advisory / non-blocking.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config → renderer | `app.reset-password-url` is trusted config; the reset link base must originate here, never from an HTTP request header. |
| app → email provider seam | Messages leave the app through `EmailSender`; the raw reset token rides in the message body (email trust boundary). |
| app → logs | Log sink is lower-trust; recipient + token must not appear in cleartext. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-01 | Information Disclosure | LoggingEmailSender logs | high | mitigate | Mask recipient via `maskEmail`; never log token or message bodies (Task 1) — prohibition authored. |
| T-10-02 | Tampering | Reset-link base URL (host-header/link poisoning) | high | mitigate | Base URL injected from `app.reset-password-url` config only; never read from request (Task 2). |
| T-10-03 | Spoofing/Info Disclosure | Real network send from default provider | high | mitigate | No-op `LoggingEmailSender` is the default (`matchIfMissing=true`); concrete provider deferred (D-03); EMAIL-02 selection test (Task 3). |
| T-10-SC | Tampering | package installs (npm/pip/cargo/gradle) | high | accept | No new dependencies added this phase (RESEARCH: all libs already on classpath); no install to audit. |
</threat_model>
