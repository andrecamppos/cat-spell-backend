# Plan 05-01: WebSocket Chat Core + Message History

<objective>
**As a** matched user, **I want to** send and receive text messages in real time via WebSocket and retrieve paginated message history, **so that** I can chat with people whose cats I liked.

Delivers the core end-to-end chat slice: WebSocket connection with JWT auth → send message → persist to PostgreSQL → broadcast to recipient → retrieve history via REST. Conversations are created lazily on first message.
</objective>

<must_haves>
## Goal-Backward Verification

### Truths (from CONTEXT.md decisions)
- D-01: Separate `conversations` table with FK to match
- D-02: `conversation_participants` table with `last_read_at` and `muted` per user
- D-03: Conversations created lazily on first message — atomic creation of conversation + 2 participant rows
- D-09: JWT sent in STOMP CONNECT frame's Authorization header, validated via ChannelInterceptor
- D-10: WebSocket session outlives token — auth only on CONNECT
- D-11: Match/conversation membership validated on SUBSCRIBE only
- D-12: No SockJS fallback — native WebSocket only
- D-13: Messages ordered by server-assigned `created_at` timestamp
- D-14: Cursor-based pagination, newest first, cursor = last message timestamp
- D-15: 30 messages per page
- D-16: Maximum message length 1000 characters
- D-06: Messages have `delivered` boolean per recipient

### Must-Haves
1. WebSocket endpoint `/ws` accepts STOMP connections with JWT in CONNECT Authorization header
2. Sending a message to a matched user persists the message and broadcasts it via STOMP
3. First message atomically creates conversation + 2 participant rows
4. GET `/api/conversations/{id}/messages` returns cursor-paginated messages (30 per page, newest first)
5. Non-matched users cannot create conversations or send messages
6. Invalid/missing JWT on CONNECT is rejected
7. SUBSCRIBE to a conversation the user is not a participant of is rejected
</must_haves>

<action>
Create `com.catspell.api.chat.service.ChatService` as `@Service` with:

**sendMessage(senderId: UUID, request: SendMessageRequest): ChatMessageResponse**
1. Resolve conversation:
   - If `request.conversationId` is non-null: look up conversation, verify sender is participant
   - If `request.matchId` is non-null: look up match via `matchRepository.findById()`, verify sender is user1 or user2, then `findOrCreateConversation(match, senderId)`
   - If both null: throw `IllegalArgumentException`
2. `findOrCreateConversation(match, senderId)`:
   - Check `conversationRepository.findByMatchId(match.id!!)` — if exists, return it
   - Otherwise `@Transactional`: create Conversation, create 2 ConversationParticipant rows (for both match users), save and return
3. Create `Message` entity, set `conversation`, `sender` (via userRepository.getReferenceById), `content`, save
4. Update `conversation.lastMessageAt = Instant.now()`, save conversation
5. Look up sender's display name via `userProfileRepository.findByUserId(senderId)?.displayName ?: "Unknown"`
6. Broadcast via `SimpMessagingTemplate.convertAndSend("/topic/chat/${conversation.id}", chatMessageResponse)`
7. Send notification via `SimpMessagingTemplate.convertAndSendToUser(otherUserId.toString(), "/queue/notifications", ChatNotification(...))`
8. Return `ChatMessageResponse`

**getMessages(userId: UUID, conversationId: UUID, cursor: Instant?, size: Int): MessagePageResponse**
1. Verify user is participant of conversation
2. Query messages with cursor-based pagination (newest first, page size from parameter, default 30)
3. For each message, look up sender display name
4. Return `MessagePageResponse` with `nextCursor` = last message's `createdAt`, `hasMore` = result size == requested size
</action>
