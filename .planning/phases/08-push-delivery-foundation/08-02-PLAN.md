<objective>
Deliver the provider-neutral `PushProvider` abstraction and its two implementations (real FCM via the `firebase-admin` SDK, and a no-op logging provider for local/CI), the Firebase configuration/wiring with fail-fast on missing credentials, and a Firebase health indicator. Call sites depend only on `PushProvider` so direct APNs can be added later without call-site changes. `push.enabled` gates behavior; when disabled (local default) the app boots with zero Firebase setup.

Implements decisions D-06 (base64-encoded service-account env var, no secrets in repo), D-07 (push.enabled gate: fail-fast + FCM when true, no-op logging provider when false), D-08 (Firebase health indicator reports configuration status), and D-09 (firebase-admin SDK behind the PushProvider abstraction).
</objective>

<must_haves>
- `PushProvider` is a provider-neutral interface — no Firebase types in its signature or in `PushPayload` (D-09); Firebase types are confined to `FcmPushProvider`.
- Two implementations selected by `push.enabled`: `FcmPushProvider` when `true`, `LoggingPushProvider` (no-op) when `false`/absent (D-07).
- `FcmPushProvider` uses `firebase-admin` `FirebaseMessaging.send(message, dryRun)` and maps `FirebaseMessagingException` with `MessagingErrorCode.UNREGISTERED` to a distinct result status (consumed by plan 03).
- Service-account JSON supplied as a base64-encoded env var; no secrets in the repo (D-06).
- When `push.enabled=true`, startup fails fast if the credential is missing/blank or fails to decode/parse (PUSH-11).
- `FirebaseHealthIndicator` reports configuration status (enabled/disabled/up), joins the actuator health group next to db/s3/webSocket, and does NOT hard-fail the aggregate when push is intentionally disabled (D-08).

truths:
  - "D-06: Service-account JSON supplied as a base64-encoded env var; no secrets in repo"
  - "D-07: push.enabled gates behavior — true=fail-fast on missing creds + real FCM; false=no-op logging provider (local default)"
  - "D-08: Firebase health indicator reports configuration status, following the existing HealthIndicator pattern"
  - "D-09: firebase-admin SDK behind the PushProvider interface; all call sites depend only on the abstraction"
  - "PUSH-09: Delivery via FCM HTTP v1 behind a PushProvider abstraction; APNs addable later without call-site changes"
  - "PUSH-11: Health indicator reports Firebase/FCM configuration status; startup fails fast if credentials are missing"

prohibitions:
  - statement: "Firebase/FCM types (Message, FirebaseMessaging, FirebaseMessagingException) MUST NOT appear in PushProvider or PushPayload"
    status: resolved
    verification: "PushProvider.kt has no com.google.firebase imports; only FcmPushProvider.kt imports firebase types"
  - statement: "The health indicator MUST NOT perform a live FCM send (no external round-trip on scrape)"
    status: resolved
    verification: "FirebaseHealthIndicator reports config status only; no FirebaseMessaging.send call"
  - statement: "Service-account JSON MUST NOT be committed to the repo or logged"
    status: resolved
    verification: ".env.example has an empty FIREBASE_CREDENTIALS_BASE64 slot; no credential value in source; credential not logged"
</must_haves>

<threat_model>
ASVS L1 — block on: high.

- **T-08-03 (credential exposure, HIGH — mitigated):** The Firebase service-account JSON grants send rights to the project. **Mitigation:** supplied only as the base64 env var `FIREBASE_CREDENTIALS_BASE64` (D-06); `.env.example` ships an empty slot; the value is never written to source and never logged (decode → `GoogleCredentials.fromStream`, no `log.info(credential)`). `.env` is gitignored (existing). Verified by a source check that no credential literal exists and by asserting the config path reads from the env-backed property.
- **T-08-04 (health/info disclosure, LOW — mitigated by existing config):** `/actuator/health` component details could leak configuration. **Mitigation:** `application.yml` already sets `show-details`/`show-components: when-authorized`; the Firebase indicator exposes only a coarse status/`push` detail (`enabled`/`disabled`), never the credential.
- **T-08-05 (running misconfigured, MED — mitigated):** Silently running with `push.enabled=true` but broken creds would drop notifications. **Mitigation:** fail-fast at startup (PUSH-11) aborts context init on missing/invalid credential, surfacing the misconfiguration immediately.
</threat_model>

Import `org.springframework.boot.autoconfigure.condition.ConditionalOnProperty`.
</action>

- `@Bean fun firebaseApp(): FirebaseApp` — fail fast: if `credentialsBase64.isBlank()` throw `IllegalStateException("push.enabled=true but FIREBASE_CREDENTIALS_BASE64 is missing")`. Decode base64 (`Base64.getDecoder().decode(...)`), build `GoogleCredentials.fromStream(ByteArrayInputStream(decoded))` (this throws on malformed JSON → fail-fast). Guard double-init: `if (FirebaseApp.getApps().isEmpty()) FirebaseApp.initializeApp(FirebaseOptions.builder().setCredentials(creds).build()) else FirebaseApp.getInstance()`.
- `@Bean fun firebaseMessaging(app: FirebaseApp): FirebaseMessaging = FirebaseMessaging.getInstance(app)`.
Mirror `S3Config`'s `@Configuration` + `@Value` bean style.

`FirebaseHealthIndicator.kt` (package `com.catspell.api.common.health`): `@Component class FirebaseHealthIndicator(@Value("\${push.enabled:false}") private val pushEnabled: Boolean, private val firebaseApp: ObjectProvider<FirebaseApp>) : HealthIndicator`. In `health()`:
- if `!pushEnabled` → `Health.up().withDetail("push", "disabled").build()` (must not DOWN the aggregate).
- if enabled and `firebaseApp.ifAvailable != null` → `Health.up().withDetail("push", "enabled").build()`.
- if enabled but no FirebaseApp bean → `Health.down().withDetail("push", "enabled-but-uninitialized").build()`.
Use `org.springframework.beans.factory.ObjectProvider` so the indicator works whether or not the FirebaseApp bean exists. No FCM send.
</action>
