<action>
Add native @Query to SwipeRepository for the discovery feed. The query must:
1. SELECT from cat_profiles cp JOIN user_profiles up ON up.user_id = cp.user_id
2. Also self-join user_profiles for requester's preferences
3. WHERE cp.user_id != :requesterId (exclude own cats)
4. AND ST_DWithin(up.location::geography, ST_SetSRID(ST_MakePoint(:lng, :lat), 4326)::geography, :maxDistanceMeters)
5. AND bidirectional gender preference check (requester.gender_preference matches up.gender and vice versa, with EVERYONE handling)
6. AND bidirectional age range check using EXTRACT(YEAR FROM AGE(CURRENT_DATE, date_of_birth))
7. AND profile completeness: up.display_name IS NOT NULL, up.bio IS NOT NULL, up.location IS NOT NULL
8. AND EXISTS active user photo, AND EXISTS active cat photo
9. AND NOT EXISTS (swipes WHERE swiper_id = :requesterId AND cat_id = cp.id)
10. ORDER BY random(), LIMIT :pageSize OFFSET :offset
11. Include inline subqueries for first cat photo thumbnail and first owner photo thumbnail
12. Include ROUND(ST_Distance(...) / 1000) AS distance_km

Create DiscoveryService with:
- getFeed(userId: UUID, cursor: String?, pageSize: Int): FeedResponse — decodes cursor (Base64 JSON with seed+offset), loads requester's UserProfile, validates location exists (throw LocationRequiredException if null), calls setseed + feed query, builds response with next cursor

Use GeometryFactory(PrecisionModel(), 4326) for creating Point from requester's location coordinates (same pattern as ProfileService).

For setseed: execute native query "SELECT setseed(:seed)" before the feed query to get deterministic random ordering. Generate seed randomly for first request, decode from cursor for subsequent pages.

<threat_model>
## Threat Model

### T1: IDOR — Viewing Other Users' Swipe Data
- **Severity:** HIGH
- **Attack:** Attacker manipulates API to see who swiped on them (violates D-11 one-sided-likes-invisible)
- **Mitigation:** No endpoint exposes swipe data. Feed query only uses swipes for exclusion. Match endpoint only returns mutual matches.

### T2: Self-Swipe / Swipe Manipulation
- **Severity:** MEDIUM
- **Attack:** User swipes on own cat to game the system
- **Mitigation:** SelfSwipeException thrown when swiper_id == cat's user_id. Validated in service layer before insert.

### T3: Location Data Leakage
- **Severity:** HIGH
- **Attack:** Feed returns raw GPS coordinates, enabling stalking
- **Mitigation:** Feed returns distance_km as rounded integer only (D-04). No raw lat/lng in feed response. Follows Phase 2 D-16 (relative distance only).

### T4: Feed Enumeration
- **Severity:** LOW
- **Attack:** Exhaustive swiping to enumerate all users in area
- **Mitigation:** Acceptable for v1. Rate limiting deferred to Phase 6.

### T5: Match Race Condition (Double Match)
- **Severity:** MEDIUM
- **Attack:** Concurrent likes create duplicate matches
- **Mitigation:** UNIQUE index on (LEAST(user1_id, user2_id), GREATEST(user1_id, user2_id)) + INSERT ON CONFLICT DO NOTHING. Database-level atomicity.
</threat_model>
