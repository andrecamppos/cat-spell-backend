<objective>
Profile CRUD Vertical Slice: Deliver profile creation, retrieval, update, and GPS location storage — the first half of the user identity system. After this plan, an authenticated user can create their profile with all required fields (display name, bio, DOB, gender, dating preferences), view it, update it, and set their GPS location stored as a PostGIS geometry point.

Also migrates test infrastructure from H2 to Testcontainers PostgreSQL+PostGIS, which is prerequisite for all Phase 2+ work.

Decisions implemented: D-01 (preferences: gender pref, age range, max distance), D-02 (binary gender model), D-03 (no defaults), D-04 (age bounds 18–99), D-11 (store DOB not age), D-12 (bio max 1000), D-14 (location updated via API), D-15 (PostGIS POINT), D-16 (raw coordinates stored, distance-only exposure is Phase 4 concern).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API | Untrusted profile data and GPS coordinates from mobile app |
| API → Database | Service-layer validated data persisted to PostgreSQL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | /api/profile | mitigate | All endpoints require JWT auth; userId extracted from token, not request body — user cannot create/modify another user's profile |
| T-02-02 | Tampering | Profile data | mitigate | Jakarta validation on all inputs: @Size, @Min/@Max, @Past, enum checks. Bio max 1000, age 18–99, valid coordinate ranges |
| T-02-03 | Information Disclosure | GPS coordinates | mitigate | D-16: raw coordinates stored but never exposed to other users. Phase 4 will only expose relative distance. This phase stores securely and returns to profile owner only |
| T-02-04 | Information Disclosure | User enumeration | accept | Profile endpoints only access own data via JWT userId. No endpoint to look up other profiles yet (that's Phase 4 discovery) |
| T-02-05 | Denial of Service | Profile creation | accept | No rate limiting in Phase 2; deferred to Phase 6. One profile per user constraint limits abuse surface |
| T-02-06 | Elevation of Privilege | Cross-user access | mitigate | userId always extracted from JWT token principal, never from request parameters. Service layer enforces ownership |
</threat_model>
