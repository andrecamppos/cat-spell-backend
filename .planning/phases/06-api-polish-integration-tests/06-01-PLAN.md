# Plan 06-01: OpenAPI Docs + Rate Limiting + Health Checks

<objective>
Deliver the three production-readiness features for Phase 6: OpenAPI spec generation (spec-only, no Swagger UI), Bucket4j rate limiting on auth endpoints, and custom health indicators for S3 and WebSocket. This is a vertical MVP slice — all three features ship together so the API is hardened in one pass.
</objective>

<must_haves>
## Goal-backward verification

- OpenAPI JSON spec served at `/v3/api-docs` with correct security scheme and endpoint grouping
- Rate limiting returns 429 after 10 requests/minute to auth endpoints with proper headers
- Health endpoint returns component-level details for authenticated users (db, s3, websocket)
- All existing tests continue to pass (no regressions)

### truths
- OpenAPI spec-only, no Swagger UI (D-01)
- 5 coarser tags: Auth, User, Cats, Discovery & Matching, Chat (D-02)
- Minimal annotations — auto-generated from DTOs (D-03)
- Global Bearer JWT SecurityScheme (D-04)
- Rate limit auth endpoints only: register, login, refresh (D-05)
- IP-based rate key with X-Forwarded-For support (D-06)
- Bucket4j token-bucket, in-memory ConcurrentHashMap (D-07)
- 10 requests/minute/IP with standard headers (D-08)
- Custom S3 and WebSocket health indicators (D-09)
- No /actuator/info endpoint (D-10)
- show-details=when-authorized (D-11)
</must_haves>

## Task 5: Create RateLimitFilter with Bucket4j

<read_first>
- src/main/kotlin/com/catspell/api/common/security/JwtAuthenticationFilter.kt
- src/main/kotlin/com/catspell/api/common/exception/GlobalExceptionHandler.kt
- src/main/kotlin/com/catspell/api/common/config/SecurityConfig.kt
</read_first>

<action>
Create `com.catspell.api.common.security.RateLimitFilter` as a `jakarta.servlet.Filter`:
1. `ConcurrentHashMap<String, Bucket>` for per-IP buckets
2. `Bandwidth.classic(10, Refill.intervally(10, Duration.ofMinutes(1)))` — 10 req/min
3. IP extraction: `X-Forwarded-For` header first entry, fallback `request.remoteAddr`
4. Only intercept paths matching `/api/auth/register`, `/api/auth/login`, `/api/auth/refresh`
5. On every auth request: add `X-RateLimit-Remaining` and `X-RateLimit-Reset` headers
6. On rate limit exceeded: return 429 with `application/problem+json` body: `{"title":"Too Many Requests","status":429,"detail":"Rate limit exceeded. Try again in N seconds."}` and `Retry-After` header

Register via `@Configuration` class with `FilterRegistrationBean` setting order to `Ordered.HIGHEST_PRECEDENCE` and URL patterns `/api/auth/*`.
</action>

<acceptance_criteria>
- `RateLimitFilter.kt` exists in `com.catspell.api.common.security`
- Filter creates Bucket4j bucket with 10 tokens, 1-minute refill interval
- IP resolved from X-Forwarded-For or remoteAddr
- 429 response has `application/problem+json` content type with ProblemDetail format
- Response includes `X-RateLimit-Remaining`, `X-RateLimit-Reset` headers on auth requests
- Response includes `Retry-After` header on 429
- Filter is registered before Spring Security filter chain
</acceptance_criteria>

<threat_model>
## Security Threat Model

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Rate limit bypass via spoofed X-Forwarded-For | HIGH | Accept X-Forwarded-For only from trusted proxies. For v1 single-instance, document that X-Forwarded-For trust requires proper proxy configuration |
| OpenAPI spec exposes internal API structure | LOW | Spec is intentionally public for client development. No sensitive data in spec. Auth endpoints properly marked |
| Rate limit exhaustion by distributed IPs | MEDIUM | Single-IP limiting is v1 design. Distributed attacks require WAF/CDN-level protection (out of scope) |
| Health endpoint leaks infrastructure details | MEDIUM | show-details=when-authorized ensures only authenticated users see component breakdown. Anonymous sees UP/DOWN only |
| ConcurrentHashMap memory growth from many IPs | LOW | Acceptable for v1 single-instance. Add TTL-based eviction in v2 |
</threat_model>
