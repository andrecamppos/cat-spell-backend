## Task 1: Create RateLimitIntegrationTest

<read_first>
- src/main/kotlin/com/catspell/api/common/security/RateLimitFilter.kt
- src/test/kotlin/com/catspell/api/BaseIntegrationTest.kt
- src/test/kotlin/com/catspell/api/auth/AuthIntegrationTest.kt
</read_first>

<action>
Create `com.catspell.api.common.RateLimitIntegrationTest` extending `BaseIntegrationTest`:

Test cases:
1. `should return rate limit headers on auth requests` — POST `/api/auth/login`, verify `X-RateLimit-Remaining` and `X-RateLimit-Reset` headers present
2. `should allow requests within rate limit` — Send 10 POST requests to `/api/auth/login`, all return 401 (invalid creds) not 429
3. `should return 429 when rate limit exceeded` — Send 11 POST requests to `/api/auth/login`, 11th returns 429
4. `should return Retry-After header on 429` — Exceed limit, verify `Retry-After` header present in 429 response
5. `should return problem+json body on 429` — Exceed limit, verify response content-type is `application/problem+json` and body contains `"status":429`
6. `should not rate limit non-auth endpoints` — Send 15+ requests to an authenticated endpoint (e.g., `/api/profile`), none return 429
7. `should rate limit register endpoint` — Exceed limit on `/api/auth/register`, verify 429
8. `should rate limit refresh endpoint` — Exceed limit on `/api/auth/refresh`, verify 429

Use `@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)` with `TestRestTemplate`.
</action>

<acceptance_criteria>
- `RateLimitIntegrationTest.kt` exists with 8 test methods
- Tests verify 429 after 10 requests on all three auth endpoints
- Tests verify rate limit headers (X-RateLimit-Remaining, X-RateLimit-Reset, Retry-After)
- Tests verify ProblemDetail format on 429 response
- Tests verify non-auth endpoints are not rate limited
- `./gradlew test --tests "*RateLimitIntegrationTest"` exits 0
</acceptance_criteria>
