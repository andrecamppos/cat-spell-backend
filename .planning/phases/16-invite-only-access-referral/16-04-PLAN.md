<objective>
Compose the invite gate into the existing register flow: add the optional `inviteCode` field to `RegisterRequest`, make `AuthService.register` `@Transactional`, and insert `inviteService.validate` after the age gate and `inviteService.consume` after the user save — all conditional on `app.invite.enabled`. When the gate is off, the invite path never runs.

Purpose: This is where INV-01 (global gate), INV-03 (gated signup requires a valid unconsumed code), and INV-04's enumeration-safe contract become observable end-to-end at `POST /api/auth/register`. The `@Transactional` boundary guarantees a failed consume never leaves an orphan account.
Output: `RegisterRequest.inviteCode`, the composed `AuthService.register`, and gate-ON / public-mode / enumeration-safety integration tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/auth/register | Untrusted `inviteCode` crosses here; the server-side gate (app.invite.enabled) decides whether it is required and validated. |
| AuthService.register → InviteService + DB | validate/consume + user save must be atomic (one transaction) to avoid orphan accounts or double-consumed codes. |
| GlobalExceptionHandler | All gated-failure modes converge on one generic 403 — the enumeration boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-16 | Elevation of Privilege | gate flag authority | high | mitigate | The gate is read server-side via `@Value("\${app.invite.enabled}")`; a client cannot bypass it — no client flag is trusted (INV-01, D-09). |
| T-16-17 | Information Disclosure | gated register failure modes | high | mitigate | Missing/invalid/consumed codes all raise `InviteRequiredException` → one identical 403 body + `INVITE_REQUIRED` (INV-04, D-10). |
| T-16-18 | Tampering (integrity) | orphan account on raced consume | high | mitigate | `@Transactional register` wraps validate→save→consume; a thrown 403 from consume rolls back the user insert (Pitfall 3). |
| T-16-19 | Tampering | reused/consumed code at register | high | mitigate | consume's atomic `markConsumed` claim rejects a second use with the generic 403; the tx rolls back (INV-04, D-07). |
| T-16-20 | Denial of Service | fail-open gate on misconfiguration | medium | accept | Default is `false` (public) by design (D-09); the operator sets `INVITE_ENABLED=true` to gate — an explicit config choice, surfaced as the kept safety prohibition. Accepted at ASVS L1. |
| T-16-SC | Tampering | dependency installs | low | accept | No new dependencies this phase (RESEARCH audit: none). |
