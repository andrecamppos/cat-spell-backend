<objective>
Close audit item W1 (MOD-02, MOD-03). On WebSocket reconnect, `ChatService.deliverUnreadMessages` pushes notification previews of messages that were still undelivered when the pair was blocked or unmatched, into a conversation that is otherwise hidden and locked. After this plan, a hidden conversation (`match.endedAt != null`, or a block row in either direction) gets no reconnect push. Its undelivered messages are marked `delivered = true`, so they can't resurface after a rematch (D-04). Hidden conversations are found with one set-based query (D-05). No re-check is added at push time (D-06).

Purpose: this is the milestone audit's top item. It sits on v2.2's core safety promise that a block is enforced on every surface.
Output: one new repository query, the partitioned `deliverUnreadMessages`, and integration tests that capture pushes at the broker channel.

Known limitations, recorded and NOT changed (RESEARCH Pitfall 6 and Pattern 1, D-05):
- A message sent while matched, with the recipient offline through an unmatch and a rematch and no reconnect in between, is pushed on the first reconnect after the rematch. The conversation and its full history are visible again then, so nothing hidden leaks.
- `sendMessage` pushes live but never sets `delivered = true`, so every message is re-pushed once on the recipient's next reconnect. That is pre-existing behavior.

Reversibility: D-04 is rated **costly** in CONTEXT.md (flagged, not gated). Afterwards a suppressed message can't be told apart from one that was pushed; the `delivered` flag is the only record.

Spec-less probe fallback skipped: the phase has no requirement IDs to probe (visible skip).

Git: **stage only, never commit** (user rule; overrides any GSD commit step). Stage this plan's paths explicitly with `git add <path>`.
