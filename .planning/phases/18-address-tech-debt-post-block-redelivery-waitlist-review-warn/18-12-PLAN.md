<objective>
Close UAT gap G-18-1, the D-04 rematch residual (18-REVIEW.md WR-01). Messages left undelivered when a conversation was hidden (block or unmatch) are pushed as stale `/queue/notifications` previews if the pair rematches *before* the recipient's next reconnect.

Cause, confirmed in code:
- `sendMessage` pushes live but never sets `delivered`, so almost every message stays `delivered = false`.
- The only writes to the flag are in `ChatService.deliverUnreadMessages` (ChatService.kt:286 and :304). They run only on a reconnect, so suppression happens only when the recipient reconnects while the conversation is still hidden.
- `MatchService.createMatch`'s reactivation branch (MatchService.kt:41-46) clears `endedAt`/`endedReason` and publishes `MatchCreatedEvent` without touching message state.

After this plan, the reactivation branch runs one set-based UPDATE, `MessageRepository.markAllDeliveredForMatch`. It marks every still-undelivered message of that match's conversation as delivered before `MatchCreatedEvent` is published. So no pre-block or pre-unmatch message can come back as a preview after a rematch, whether or not anyone reconnected in between (D-04).

The user chose option (b) at UAT. D-05 ("the fix lives only on the reconnect path") is therefore amended with exactly one exception: the reactivation branch. Block/unmatch teardown (`MatchService.endMatch`) stays unchanged.

Purpose: D-04's promise that a suppressed message can't resurface after a rematch becomes unconditional. Today it holds only if the recipient happened to reconnect while the conversation was hidden.
Output: one repository method, one call in the reactivation branch, two no-reconnect-between integration tests (block and unmatch) with a post-rematch delivery control, unit tests for branch scoping and ordering, a corrected KDoc, and the D-05 amendment.

Reversibility: **costly** (flagged, not gated), the same rating as D-04. A message swept at rematch can't afterwards be told apart from one that was pushed; the `delivered` flag is the only record. Message rows and content are kept.
