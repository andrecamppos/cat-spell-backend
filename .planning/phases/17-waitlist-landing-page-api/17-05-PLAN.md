<objective>
Close WAIT-04: the operator converts one confirmed waitlist entry into an invite with `POST /api/admin/waitlist/{id}/invite` (D-09). In one transaction the service claims `CONFIRMED→INVITED`, issues an organic invite through `InviteService.create(null)` (D-10), and emails the code synchronously; if delivery fails, everything rolls back so the entry stays retryable.

Purpose: This is the hand-off from launch demand to gated signup — invitees register in the app with the emailed `inviteCode` (Phase 16). Returning the raw code in the 201 lets the operator deliver it manually, since `LoggingEmailSender` is the only sender today (RESEARCH finding 4).
Output: `markInvited`, `WaitlistService.convertToInvite`, two exceptions + their ProblemDetail mappings, `WaitlistInviteEmailRenderer`, the convert endpoint + response DTO, and `WaitlistConvertIntegrationTest`.
</objective>
