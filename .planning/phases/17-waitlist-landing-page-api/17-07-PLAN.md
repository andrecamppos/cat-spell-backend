<objective>
Close the SC3 blocker from 17-VERIFICATION.md: `RateLimitFilter.resolveClientIp` currently trusts the client-supplied `X-Forwarded-For` header unconditionally, so any caller defeats the per-IP throttle on `POST /api/waitlist` (and on every `/api/auth/*` path it shares the filter with) by rotating one header. No trusted-proxy configuration exists anywhere in the repo. This plan makes `resolveClientIp` trust `X-Forwarded-For` only when the directly-connecting peer (`request.remoteAddr`) is itself a configured trusted proxy; an untrusted caller is always keyed on its own socket address, which it cannot forge.

Purpose: T-17-17 ("X-Forwarded-For rotation bypasses the per-IP bucket") was accepted by the original planner on an unverified deployment assumption (RESEARCH A7: "production overwrites X-Forwarded-For"). 17-VERIFICATION.md found no human accepted that risk and common proxies (AWS ALB, GCP LB, default nginx) APPEND rather than overwrite, so A7 does not hold for them. This plan replaces the accepted risk with an actual mitigation.
Output: `RateLimitFilter`/`RateLimitFilterConfig` gain a `trustedProxies` set (default `{127.0.0.1, ::1}`, which is MockHttpServletRequest's default remoteAddr, so every pre-existing test keeps passing unchanged); two new/extended test files prove the fix on both the general filter infra and the exact SC3-named `POST /api/waitlist` endpoint.
</objective>
