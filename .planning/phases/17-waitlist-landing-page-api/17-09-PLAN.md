<objective>
Close the last open gap in 17-VERIFICATION.md: ROADMAP SC3's per-IP half is still bypassable. Both bypasses live in one production file, `RateLimitFilter.kt`, and both were reproduced against the compiled filter.

1. **CR-02 (any deployment):** the filter decides whether to throttle from the raw, undecoded request URI. `POST /api/%77aitlist` and `POST /api/auth/%6Cogin` skip the per-IP limit, while the firewall, Spring Security permitAll and MVC routing all decode the path and serve the request.
2. **CR-01 (behind an appending trusted proxy):** with a trusted peer, the bucket key is the client-written leftmost `X-Forwarded-For` hop. The default trust set includes 127.0.0.1, so a same-host nginx using `$proxy_add_x_forwarded_for` is exploitable with the default config.
3. **WR-09 (listed in the gap's `missing:` as recommended alongside):** trust matching is exact-string. The `::1` default never matches Tomcat's `0:0:0:0:0:0:0:1`, there is no CIDR support, and the key is neither declared nor documented.

The fix makes three changes. The filter matches on the decoded application path. The client is resolved as the rightmost `X-Forwarded-For` hop that is not a trusted proxy (Tomcat RemoteIpValve semantics, read across every header line). Trust is decided by a new family-safe `TrustedProxyMatcher` that supports exact IPs and CIDR.

The three red-confirmed tests that `/gsd-validate-phase` staged in `RateLimitBypassIntegrationTest` are re-enabled and pass with their assertions unchanged. New tests are added only where the gap's `missing:` items need coverage those three do not give: the normalized-path spelling sweep, the inner trusted hop, the second header line, IPv6 loopback, CIDR, the family guard, and fail-fast config.

Purpose: SC3 / WAIT-03 is the only failed must-have (51/52). This plan supersedes 17-07's "a trusted peer's forwarded IP is honored exactly as before" only for multi-hop chains. Single-value forwarding from a trusted peer, and the untrusted-peer behavior, are unchanged.
