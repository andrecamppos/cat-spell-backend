<objective>
Complete double opt-in (WAIT-02): the join now emails a single-use confirmation link after commit, and `GET /api/waitlist/confirm?token=...` atomically claims the token and 302-redirects to a configured web success or error URL (D-01). Only entries that complete this step reach `CONFIRMED`.

Purpose: Bots and typo'd addresses never confirm, so only real, consenting mailboxes count. Sending asynchronously after commit removes the timing side channel and keeps a mail failure from turning the join into a 500 (RESEARCH Pattern 5).
Output: confirmation event + async listener + renderer, the `claimConfirm` query, `WaitlistService.confirm`, the confirm endpoint, and `WaitlistConfirmIntegrationTest`.
</objective>
