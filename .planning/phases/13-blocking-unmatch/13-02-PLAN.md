<objective>
Wire the moderation service layer on top of Plan 13-01's schema: a `SelfBlockException` (400), the shared
`MatchService.endMatch` teardown primitive (soft-state end + swipe clear), `MatchService.unmatch`,
`createMatch` reactivation for the fresh-re-swipe path (D-08), and `BlockService` (block/unblock/getBlockList
/isBlockedEitherWay) which owns the blocks table and the bidirectional predicate. Block ⊇ unmatch (D-11):
block runs the exact same teardown then additionally writes a blocks row.

Purpose: Provide the imperative block predicate + teardown that Plan 13-03 enforcement and Plan 13-04
endpoints consume, with the self-block/idempotency/no-auto-rematch/no-rediscovery-ban semantics locked in.
Output: `moderation/service/BlockService.kt`, `MatchService` endMatch/unmatch/reactivation, `SelfBlockException`
+ handler, `BlockServiceIntegrationTest`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated caller → BlockService | The caller may only create/remove blocks they own and unmatch a match they participate in. |
| BlockService → MatchService teardown | Block must trigger the same teardown as unmatch, plus the rediscovery ban, with no path that hard-deletes evidence. |
| read/send paths → isBlockedEitherWay | The predicate must be synchronous + strongly consistent so there is no stale window where a blocked user acts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-07 | Elevation of Privilege | IDOR — acting on another user's block/unmatch relationship | high | mitigate | block/unblock keyed on the authenticated blockerId; unmatch requires an active match the caller is in (Task 2/3). |
| T-13-08 | Information Disclosure | Blocked user learning a block occurred via teardown side effects | high | mitigate | Teardown is silent soft state; no exception/response is surfaced to the other party from BlockService (Task 3, D-02 groundwork). |
| T-13-09 | Spoofing/Tampering | Stale or cached block check letting a blocked user through | high | mitigate | isBlockedEitherWay hits the DB every call; no cache field (Task 3, research anti-pattern). |
| T-13-10 | Tampering | Teardown destroying report evidence (hard delete) | high | mitigate | endMatch flips ended_at/ended_reason only; deleteSwipesBetween touches swipes exclusively (Task 2, D-07). |
